# Portable agent profiles

Apply the reference Codex statusline and an analogous supported Claude
statusline to personal and configured opted-in Epic accounts. Use Claude
acceptEdits and Codex workspace-write/on-request as the user's edit-automation
defaults, retaining provider, authentication, model and hook data. Agent
preferences merge through the existing installer transaction; new work profiles
receive them only after the gateway writes valid config.

An older default Claude profile may still be gateway-managed. Recognize only a
gateway helper marker or a direct claude-gateway apiKeyHelper executable, then
move the profile and unambiguous sidecar into an empty Epic destination. Back up
rewritten config bytes privately and reverse moves on migration failure. Never
merge two existing account trees. Prefer mise's real client binaries for gateway
dependency checks; verify profile files before reporting setup success.

Keeping the old work account in the personal default conflicts with directory
routing. Creating empty work settings conceals incomplete gateway setup.
The selected approach migrates recognized legacy state and validates actual
gateway output, with snapshots before installation and preservation of already
complete client configs. Current Omarchy and Ubuntu24.04+ provide required
Python3.11+; older stock Python fails preflight before installation writes.
